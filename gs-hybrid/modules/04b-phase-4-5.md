# 04b - Phase 4-5: QA 评审与 CSO 安全评审

## Phase 4: QA 评审

**触发条件**: L3 任务 (L1/L2 可选)

**调用 Skill**: `/qa`

### 目标

从质量保障角度审查，确保测试策略完善，边界条件覆盖充分。

### 测试策略检查

#### 4.1 单元测试

- [ ] **覆盖率要求**
  - 核心逻辑覆盖率 >= 80%
  - 关键路径覆盖率 >= 90%
  - 边界条件覆盖率 >= 100%

- [ ] **测试质量**
  - 测试是否独立
  - 测试是否可重复
  - 测试是否快速

- [ ] **测试场景**
  - 正常场景
  - 异常场景
  - 边界场景

#### 4.2 集成测试

- [ ] **接口测试**
  - 输入验证
  - 输出验证
  - 错误处理

- [ ] **数据流测试**
  - 数据转换
  - 数据持久化
  - 数据一致性

#### 4.3 端到端测试

- [ ] **用户场景**
  - 主流程
  - 备选流程
  - 异常流程

### 边界条件识别

#### 输入边界
- [ ] 空值/零值
- [ ] 最大值/最小值
- [ ] 特殊字符
- [ ] 超长输入

#### 状态边界
- [ ] 初始状态

- [ ] 并发状态

#### 资源边界
- [ ] 内存限制

- [ ] 存储限制

## Phase 5: CSO 安全评审

**触发条件**: L3 任务 (L1/L2 可选)

**调用 Skill**: `cso`

### 目标

从安全角度审查，识别潜在的安全漏洞和风险。

### 安全检查清单

#### 5.1 输入验证

- [ ] **SQL 注入**
  - 所有用户输入是否经过参数化
  - 动态查询是否安全
  - ORM 使用是否正确

- [ ] **XSS 防护**
  - 输出是否转义
  - 富文本处理是否安全
  - CSP 是否配置

- [ ] **命令注入**
  - 是否执行用户输入的命令
  - 系统调用是否安全
  - 路径遍历防护

#### 5.2 认证与授权

- [ ] **身份认证**
  - 密码策略是否合规
  - 会话管理是否安全
  - MFA 是否支持

- [ ] **权限控制**
  - 最小权限原则
  - 水平越权检查
  - 垂直越权检查

- [ ] **Token 安全**
  - JWT 配置是否正确
  - Token 过期策略
  - Token 刷新机制

#### 5.3 敏感信息

- [ ] **密钥管理**
  - 密钥是否硬编码
  - 密钥轮换机制
  - 密钥存储安全

- [ ] **日志脱敏**
  - 敏感信息是否脱敏
  - 日志访问控制
  - 日志保留策略

- [ ] **配置安全**
  - 配置文件权限
  - 环境变量使用
  - 敏感配置加密

#### 5.4 通信安全

- [ ] **传输加密**
  - TLS 配置
  - 证书管理
  - 加密算法选择

- [ ] **API 安全**
  - 速率限制
  - 请求大小限制
  - CORS 配置

## 安全异常处理

### 发现安全问题的处理流程

```
发现问题 → 评估风险 → 紧急修复 → 重新评审
```

### 风险分级

| 级别 | 定义 | 响应时间 | 处理方式 |
|------|------|---------|---------|
| **Critical** | 可导致系统被完全攻破 | 立即 | 停止所有工作，立即修复 |
| **High** | 可导致严重数据泄露 | 24小时 | 优先修复 |
| **Medium** | 可导致有限影响 | 1周内 | 计划修复 |
| **Low** | 影响较小 | 下次迭代 | 记录跟踪 |

### 修复验证

修复后必须：
1. 重新运行安全扫描
2. 验证修复有效性
3. 确认无回归问题
4. 更新安全文档
