# 05 - Phase 6-7: 编码实现与验证交付

## Phase 6: 编码实现

**触发条件**: 所有级别任务 (L1/L2/L3)

**调用 Skill**: `test-driven-development`

### 目标

按照 TDD 流程进行编码，确保代码质量和测试覆盖。

### TDD 流程

```
编写测试 → 运行测试(失败) → 编写代码 → 运行测试(通过) → 重构 → 重复
```

### 编码规范

#### 6.1 测试先行

- [ ] 先写测试，再写实现
- [ ] 测试失败时才写实现
- [ ] 只写足够的代码让测试通过

#### 6.2 小步快跑

- [ ] 每个提交只做一件事
- [ ] 频繁提交，小粒度
- [ ] 每次提交都可运行

#### 6.3 持续验证

- [ ] 每次修改后运行测试
- [ ] 保持测试通过
- [ ] 及时修复失败

### 编码检查清单

#### 代码质量
- [ ] 遵循项目代码规范
- [ ] 函数长度 <= 50 行
- [ ] 圈复杂度 <= 10
- [ ] 无重复代码

#### 错误处理
- [ ] 所有错误被处理
- [ ] 错误信息清晰
- [ ] 错误日志完整

#### 文档注释
- [ ] 公共 API 有文档
- [ ] 复杂逻辑有注释
- [ ] 变更记录更新

### 提交规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type**:
- feat: 新功能
- fix: 修复
- docs: 文档
- style: 格式
- refactor: 重构
- test: 测试
- chore: 构建/工具

### 输出要求

生成《编码实现报告》：

```markdown
# 编码实现报告

## 实现统计

- 新增文件: X 个
- 修改文件: X 个
- 删除文件: X 个
- 新增代码: XXX 行
- 新增测试: XXX 行
- 测试覆盖率: XX%

## 提交记录

| 提交 | 类型 | 说明 |
|------|------|------|
| abc123 | feat | 实现功能 X |
| def456 | test | 添加测试 |

## 代码质量

- [ ] 规范检查通过
- [ ] 复杂度达标
- [ ] 无重复代码

## 测试结果

- [ ] 单元测试通过
- [ ] 集成测试通过
- [ ] 覆盖率达标
```

## Phase 7: 验证交付

**触发条件**: 所有级别任务 (L1/L2/L3)

**调用 Skill**: `verification-before-completion`, `/qa`

### 目标

完成最终验证，确保交付质量，生成交付物。

### 验证清单

#### 7.1 功能验证

- [ ] **需求覆盖**
  - 所有需求已实现
  - 验收标准已满足
  - 边界条件已处理

- [ ] **场景测试**
  - 正常场景通过
  - 异常场景通过
  - 边界场景通过

#### 7.2 质量验证

- [ ] **代码质量**
  - Lint 检查通过
  - 代码审查通过
  - 复杂度达标

- [ ] **测试质量**
  - 单元测试通过
  - 集成测试通过
  - 覆盖率达标

- [ ] **性能质量**
  - 响应时间达标
  - 资源使用合理
  - 并发性能达标

#### 7.3 安全验证

- [ ] **安全扫描**
  - 无高危漏洞
  - 无中危漏洞(或有修复计划)
  - 依赖安全检查通过

- [ ] **敏感信息**
  - 无硬编码密钥
  - 日志无敏感信息
  - 配置安全
