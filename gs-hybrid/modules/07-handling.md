# 07 - 异常处理机制

## 异常类型

| 类型 | 描述 | 处理方式 |
|------|------|---------|
| **流程阻断** | 用户未确认、配置缺失 | 等待或提示补充 |
| **评审失败** | 工程规范、架构、安全检查未通过 | 修复或接受风险 |
| **执行失败** | 测试失败、构建失败 | 修复后重试 |
| **方案变更** | 用户中途变更需求 | 重新评估影响 |
| **外部依赖** | 第三方服务不可用 | 降级或等待 |

## 回滚机制

### 触发条件

- 方案变更需要回退
- 评审不通过需要重做
- 用户要求放弃当前方案
- Debug 流程中 3+ 假设失败需要重新评估

### 回滚级别

| 级别 | 回退到 | 触发条件 |
|------|--------|---------|
| **L1** | Phase 0.6 | 方案选择变更 |
| **L2** | Phase 1.5 | PLAN 需要修改 |
| **L3** | Phase 0.5 | 设计需要重新考虑 |
| **L4** | Step 0 | 复杂度评估错误 |
| **D1** | D2 Root Cause | 假设验证失败，需要重新调查 |
| **D2** | D1 Symptom Lock | Bug 分级错误，需要重新评估 |
| **D3** | D4 Hypothesis | 3+ 假设失败，需要质疑架构 |

### 回滚流程

```
识别回滚需求 → 确定回滚级别 → 清理当前状态 → 恢复上一阶段 → 继续执行
```

### 回滚检查清单

- [ ] 清理当前阶段的临时文件
- [ ] 恢复上一阶段的文档状态
- [ ] 通知用户回滚完成
- [ ] 记录回滚原因

## 方案变更审批流程

### 变更类型

| 类型 | 说明 | 审批要求 |
|------|------|---------|
| **范围变更** | 增加/减少功能范围 | 需要重新评估复杂度 |
| **技术变更** | 更换技术方案 | 需要重新 Design Doc |
| **时间变更** | 调整时间计划 | 需要风险评估 |
| **资源变更** | 调整资源分配 | 需要影响分析 |

### 变更流程

```
提出变更 → 影响分析 → 方案对比 → 用户确认 → 更新文档 → 继续执行
```

## 评审异常处理

### 发现问题时的处理

#### 阻断性问题

```
发现阻断性问题 → 立即停止 → 修复问题 → 重新评审 → 继续流程
```

#### 严重性问题

```
发现严重性问题 → 记录问题 → 用户决策 → 修复/接受风险 → 继续/记录债务
```

#### 一般性问题

```
发现一般性问题 → 记录待办 → 继续流程 → 后续优化
```

### 用户决策选项

当评审发现问题时，提供以下选项：

1. **立即修复** - 暂停流程，先修复问题
2. **继续但记录** - 继续流程，记录技术债务
3. **接受风险** - 明确接受风险，继续执行
4. **重新设计** - 问题太大，回到设计阶段

## Debug 流程异常处理

### 3-Strike 规则触发

当 D4 (Hypothesis & Fix) 阶段 3 次假设均失败：

```
STOP → AskUserQuestion →
  A) 继续调查 — 有新假设
  B) 升级人工审查
  C) 添加日志，等待复现
```

### Bug 分级错误

若调试过程中发现实际复杂度高于分级：

| 原分级 | 实际复杂度 | 处理 |
|--------|-----------|------|
| Quick | Standard | 暂停，补做 D2/D3，继续 |
| Quick/Standard | Deep | 暂停，AskUserQuestion 确认是否继续 |

### Scope Creep 防护

若修复过程中发现需要修改锁定范围外的文件：

1. 记录发现
2. AskUserQuestion 确认是否扩展范围
3. 若扩展，更新 freeze-dir.txt
4. 若不扩展，标记 DONE_WITH_CONCERNS 并记录

## 度量指标 (KPI)

### 流程效率指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| **需求澄清率** | Phase 0.6 一次通过率 | >= 80% |
| **PLAN 确认率** | Phase 1.5 一次通过率 | >= 70% |
| **评审通过率** | Phase 2-5 一次通过率 | >= 60% |
| **返工率** | 需要回滚的比例 | <= 20% |
| **Debug 首次修复率** | D4 阶段一次修复成功率 | >= 70% |
| **Debug 平均耗时** | 从 D1 到 D5 的平均时间 | Quick<=30min, Standard<=2h |

### 代码质量指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| **测试覆盖率** | 代码覆盖率 | >= 80% |
| **缺陷密度** | 每千行代码缺陷数 | <= 0.5 |
| **技术债务** | 记录的技术债务数 | 持续减少 |

### 安全指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| **高危漏洞** | 生产环境高危漏洞数 | 0 |
| **中危漏洞** | 未修复中危漏洞数 | <= 3 |
| **安全扫描通过率** | 安全扫描通过比例 | 100% |

### 流程优化机制

1. **定期回顾** - 每个迭代/里程碑进行回顾
2. **数据分析** - 基于 KPI 数据分析问题
3. **实验改进** - 小范围实验新流程
4. **文档更新** - 及时更新流程文档
5. **知识分享** - 分享最佳实践
