# 02 - 复杂度分级、适用矩阵

## 任务复杂度分级

根据变更范围、影响面和风险等级，将任务分为三级：

### 判定标准

| 维度 | L1 简单 | L2 中等 | L3 复杂 |
|------|---------|---------|---------|
| 变更文件数 | < 3 | 3-8 | > 8 |
| 新增代码行 | < 100 | 100-500 | > 500 |
| 接口变更 | 无 | 新增 | 修改/删除 |
| 架构影响 | 无 | 局部 | 全局 |
| 依赖变更 | 无 | 新增依赖 | 替换核心依赖 |
| 风险等级 | 低 | 中 | 高 |

### 复杂度判定决策树

```
开始
  │
  ├─ 是否涉及架构重构？
  │   ├─ 是 → L3
  │   └─ 否 ↓
  │
  ├─ 是否涉及安全或性能关键路径？
  │   ├─ 是 → L3
  │   └─ 否 ↓
  │
  ├─ 修改文件数 > 8？
  │   ├─ 是 → L3
  │   └─ 否 ↓
  │
  ├─ 新增代码 > 500 行？
  │   ├─ 是 → L3
  │   └─ 否 ↓
  │
  ├─ 修改文件数 >= 3？
  │   ├─ 是 ↓
  │   │   ├─ 新增接口或模块？ → L2
  │   │   └─ 影响现有功能？ → L2
  │   └─ 否 ↓
  │
  └─ L1 (简单任务)
```

## 各级别流程定义

### L1 - 简单任务 (轻量级流程)

**判定标准** (满足任一):
- 修改文件 < 3 个
- 新增代码 < 100 行
- 纯 bug 修复，无架构变更
- 文档更新

**简化流程**:
```
Step 0 → Phase 0.6 → Phase 1 → Phase 1.5 → Phase 6 → Phase 7
```

**要求**: 
- Phase 0.6 和 Phase 1.5 必须执行，不能跳过
- 可跳过 Design Doc (Phase 0.5)
- 可跳过多角色评审 (Phase 2-5)

### L2 - 中等任务 (标准流程)

**判定标准** (满足任一):
- 修改文件 3-8 个
- 新增代码 100-500 行
- 新增接口或模块
- 影响现有功能

**标准流程**:
```
Step 0 → Phase 0.5 → Phase 0.6 → Phase 1 → Phase 1.5 → Phase 2-3 → Phase 6 → Phase 7
```

**注意**: 
- Phase 0.6 和 Phase 1.5 必须执行
- 需要 Phase 0.5 (Design Doc)
- 需要 Phase 2-3 (工程规范 + 架构评审)
- 可跳过 Phase 4-5 (QA/安全评审)

### L3 - 复杂任务 (完整流程)

**判定标准** (满足任一):
- 修改文件 > 8 个
- 新增代码 > 500 行
- 架构重构
- 涉及安全或性能关键路径

**完整流程**:
```
Step 0 → Phase 0.5 → Phase 0.6 → Phase 1 → Phase 1.5 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 6 → Phase 7
```

**要求**: 所有阶段必须执行

| Phase | 名称 | L1 | L2 | L3 | 说明 |
|:-----:|------|:--:|:--:|:--:|------|
| 0 | 复杂度评估 | ✅ | ✅ | ✅ | 所有任务必须 |
| 0.5 | Design Doc | ⚪ | 🔴 | 🔴 | L2+ 必须 |
| 0.6 | 方案审核确认 | 🔴 | 🔴 | 🔴 | 所有级别必须 |
| 1 | 逻辑规划 | ✅ | ✅ | ✅ | 所有级别必须 |
| 1.5 | Plan验证确认 | 🔴 | 🔴 | 🔴 | 所有级别必须 |
| 2 | 工程规范设计 | ⚪ | 🟡 | 🔴 | L1 可选，L2+ 必须 |
| 3 | 架构师评审 | ⚪ | 🟡 | 🔴 | L1 可选，L2+ 必须 |

| 5 | CSO 安全评审 | ⚪ | ⚪ | 🔴 | L3 必须 |
| 6 | 编码实现 | ✅ | ✅ | ✅ | 所有级别必须 |
