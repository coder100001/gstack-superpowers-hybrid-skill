## 2. 已识别风险约束

### 技术风险
- **风险**: 上游技能更新可能破坏兼容性
  - **约束**: 所有更新必须经过测试验证
  - **缓解**: 版本锁定，按需同步
  - **监控**: `.upstream-versions.json` 跟踪版本

- **风险**: 上下文 token 超限
  - **约束**: 模块按需加载，单模块 < 10KB
  - **缓解**: 模块化设计，按需 hydration
  - **监控**: 定期检查模块大小

### 流程风险
- **风险**: 用户确认环节导致流程阻塞
  - **约束**: 仅关键决策点需要确认
  - **缓解**: 明确标记 <HARD-GATE>
  - **监控**: 记录确认耗时

### 质量风险
- **风险**: 技能调用失败导致流程中断
  - **约束**: 所有技能调用必须有降级方案
  - **缓解**: 异常处理模块，可回滚
  - **监控**: 失败率统计

## 3. 性能约束

### 响应时间
- **复杂度评估 (Step 0)**: < 2s
- **需求澄清 (DISCOVERY)**: < 10s
- **计划编写 (TASK_DECOMPOSITION)**: < 15s
- **代码实现 (IMPLEMENTATION)**: 无硬性限制，保持流畅
- **验证交付 (SHIP_REVIEW)**: < 20s

### 资源消耗
- **初始上下文加载**: < 20KB token
- **峰值上下文加载**: < 30KB token
- **单模块大小**: < 10KB
- **总契约大小**: < 50KB

### 并发能力
- **支持的并行任务**: 1（单用户场景）
- **后台任务并行度**: 无（串行执行）
- **工具调用并发**: 根据具体工具限制

## 4. 安全约束

### 代码安全
- 禁止硬编码密钥、令牌、密码
- 禁止在日志中输出 PII（个人身份信息）
- 所有外部输入必须验证
- 禁止执行未经验证的动态代码

### 数据安全
- 敏感配置必须通过环境变量传递
- 本地数据不得上传到第三方服务（除非明确授权）
- 临时文件必须清理
- 加密算法必须使用行业标准（AES-256, RSA-2048+）

### 访问控制
- 技能调用必须符合权限范围
- 文件操作限制在工作目录内
- 网络访问必须通过代理（如配置）
- 禁止越权访问系统资源

---

## 5. 可维护性约束

### 代码质量
- 所有代码必须有注释（关键逻辑）
- 函数/模块职责单一
- 遵循 SOLID 原则
- 避免重复代码（DRY 原则）

### 文档要求
- 新增功能必须更新对应文档
- 架构变更必须有 ADR
- 接口变更必须有迁移指南
- 所有技能必须有 SKILL.md

### 测试要求
- 核心逻辑必须有单元测试
- L2+ 变更必须有集成测试
- L3 变更必须有端到端测试
- 测试覆盖率目标：核心模块 > 80%

---

## 6. 兼容性约束

### 向后兼容
- 所有公开 API 必须向后兼容
- 不兼容变更必须版本化
- 废弃功能必须保留至少 2 个版本周期
- 废弃 API 必须有明确的迁移路径

### 平台兼容
- 支持 macOS（主要开发平台）
- 支持 Linux（服务器环境）
- Windows 支持为最佳努力（不保证）
- Node.js 版本 >= 18, Deno 版本 >= 1.30

### 工具兼容
- Shell 脚本兼容 Bash/Zsh
- Python 脚本兼容 3.8+
- 所有依赖必须在 package.json 锁定

## 7. 协作约束

### 版本控制
- 所有变更必须有清晰的 commit message
- L2+ 变更必须通过 PR
- L3 变更必须多人评审
- 主分支必须保持可发布状态

### 变更流程
- L1: 直接提交 → 记录
- L2: 设计 → 确认 → 实现 → 测试 → 提交
- L3: 完整流程 → 多轮评审 → 确认 → 实现 → 测试 → 提交

### 沟通规范
- 架构决策必须记录在 ADR
- 风险必须提前识别并沟通
- 问题必须及时上报
- 知识必须共享到文档

---

## 8. 禁止模式

### 代码级禁止
- 禁止使用 `any` / `interface{}` 作为公开 API
- 禁止吞没错误（empty catch / `_ = err`）
- 禁止硬编码配置值
- 禁止循环依赖
- 禁止在构造函数中执行 IO

### 流程级禁止
- 禁止绕过 Decision Layer 直接执行 L2+ 变更
- 禁止跳过用户确认环节（<HARD-GATE>）
- 禁止未测试就合并到主分支
- 禁止破坏已有契约

### 协作级禁止
- 禁止未沟通就进行架构变更
- 禁止忽略代码审查意见
- 禁止提交不完整的功能
- 禁止删除他人代码未沟通
