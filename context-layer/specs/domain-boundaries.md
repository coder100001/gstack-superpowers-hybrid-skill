## 2. 各领域详细定义

### Context Domain（上下文契约域）
- **职责**: 定义项目约束、架构规范、领域边界
- **位置**: `context-layer/`
- **核心模块**:
  - `specs/` - 契约规范
  - `hydration/` - 上下文加载
- **对外接口**: Hydration API
- **依赖**: 无
- **禁止**:
  - 包含业务逻辑
  - 直接调用其他域
  - 运行时动态修改契约

### Orchestration Domain（流程编排域）
- **职责**: 复杂度评估、阶段调度、技能路由
- **位置**: `skills/hybrid/gs-hybrid-v3/`
- **核心模块**:
  - 复杂度评估模块
  - 阶段调度模块
  - 技能路由模块
- **对外接口**: 主流程入口
- **依赖**: Context Domain, Skills Domain
- **禁止**:
  - 直接实现具体技能
  - 绕过 Context 约束
  - 执行持久化操作

### Execution Domain（执行交付域）
- **职责**: 代码实现、测试执行、文档生成、部署验证
- **位置**: `execution-layer/` + 项目根目录
- **核心模块**:
  - 代码实现引擎
  - 测试执行引擎
  - 文档生成器
- **对外接口**: Implementation API
- **依赖**: Context Domain, Orchestration Domain, Skills Domain, Tools Domain
- **禁止**:
  - 未经验证直接提交
  - 破坏项目结构
  - 绕过契约执行

### Skills Domain（技能域）
- **职责**: 提供各类技能实现
- **位置**: `skills/`
- **子域**:
  - **Superpowers 子域**: 原生 AI 工程技能
  - **GStack 子域**: 浏览器自动化和 QA 技能
  - **Hybrid 子域**: 混合编排技能
  - **Custom 子域**: 用户自定义技能
- **对外接口**: 统一 SKILL.md 接口
- **依赖**: Context Domain, Tools Domain
- **禁止**:
  - 技能间直接依赖
  - 共享内部状态
  - 破坏技能隔离

### Tools Domain（工具域）
- **职责**: 提供底层工具支持
- **位置**: `gstack-skills/bin/`, `scripts/`
- **核心工具**:
  - GStack 工具集（53个）
  - 项目管理脚本
  - 事件钩子
- **对外接口**: 命令行接口
- **依赖**: 无（独立可运行）
- **禁止**:
  - 依赖上层域
  - 修改项目契约
  - 执行未授权操作

## 3. 隔离规则

### 领域隔离
- 每个领域独立维护自身状态
- 领域间通过明确接口通信
- 禁止领域间直接访问内部数据
- 领域内变更不影响其他领域

### 技能隔离
- 每个技能独立运行
- 技能间不共享内存状态
- 技能通过文件/标准 IO 传递数据
- 技能失败不影响其他技能

### 工具隔离
- 工具独立可执行
- 工具通过命令行参数配置
- 工具输出结构化数据
- 工具无持久化副作用（除非明确）

## 4. 跨域通信方式

### 通信原则
- 所有跨域通信必须通过定义好的接口
- 通信数据必须结构化（JSON 优先）
- 通信必须有明确的契约
- 通信必须记录日志

### Context → 其他域
- **方式**: 文件读取（契约加载）
- **契约**: 规范的 Markdown 格式
- **方向**: 单向只读
- **频率**: 初始化时加载

### Orchestration → Skills
- **方式**: 技能调用（按 SKILL.md 契约）
- **契约**: 参数/输出定义
- **方向**: 单向请求-响应
- **频率**: 按需调用

### Orchestration → Execution
- **方式**: 计划传递 + 回调
- **契约**: PLAN.md 格式
- **方向**: 双向（计划下发 + 状态反馈）
- **频率**: 任务期间持续

### Skills → Tools
- **方式**: 命令行调用
- **契约**: CLI 参数 + 退出码
- **方向**: 单向请求-响应
- **频率**: 按需调用

## 5. 数据流转规范

### 数据流方向
```
用户输入
    ↓
Orchestration (复杂度评估)
    ↓
Skills (按需调用)
    ↓
Execution (代码实现)
    ↓
输出交付
```

### 数据契约
- **ADR**: `decision-layer/adr/ADR-NNN-title.md`
- **实现计划**: `specs/plans/PLAN-XXX.md`
- **中间状态**: 临时文件（规范位置）
- **最终输出**: 项目文件 + 报告

### 数据一致性
- 所有数据变更必须可追踪
- 关键数据必须有版本
- 数据格式必须向后兼容
- 数据清理必须明确

## 6. 禁用模式

### 跨域禁用
- 禁止绕过接口直接访问其他域内部
- 禁止跨域共享内存状态
- 禁止跨域直接修改数据
- 禁止循环依赖

### 领域内禁用
- Context 域：禁止包含业务逻辑
- Orchestration 域：禁止实现具体技能
- Skills 域：禁止技能间直接依赖
- Tools 域：禁止依赖上层

### 通信禁用
- 禁止隐式数据传递
- 禁止无契约通信
- 禁止同步阻塞调用（除非明确）
- 禁止未日志记录的通信

---

## 7. 领域演进规则

### 新增领域
- 必须经过 Decision Layer 审批
- 必须明确职责和边界
- 必须定义接口契约
- 必须更新此文档

### 修改领域
- L1: 内部优化，不影响接口
- L2: 接口变更，向后兼容
- L3: 架构重构，全局影响

### 废弃领域
- 必须有明确的迁移路径
- 必须保留至少 2 个版本周期
- 必须通知所有使用者
- 必须更新所有相关文档
