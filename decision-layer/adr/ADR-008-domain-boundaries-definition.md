# ADR-008: 领域边界正式定义

- **状态**: ✅ 活跃
- **日期**: 2026-05-16
- **影响范围**: context-layer/specs/domain-boundaries.md

## 背景

多个领域共存但缺乏明确的边界定义，导致实践中频繁出现跨域越权访问、隐式依赖和职责重叠。例如技能域直接调用工具域的内部函数，编排域包含业务逻辑。

## 决策

正式定义领域边界和隔离规则：

- 每个领域独立维护自身状态，通过明确接口通信
- 跨域通信必须使用结构化数据（JSON 优先）
- 领域间禁止共享内部状态和直接访问内部数据
- 每个领域的"禁止"规则明确写入领域契约
- 新增或修改领域必须通过 Decision Layer 审批

## 后果

- **正面**: 领域职责清晰，杜绝越权访问
- **正面**: 领域可独立演进，变更影响局部化
- **正面**: 新领域加入有章可循
- **负面**: 严格的隔离规则增加跨域通信的设计成本
- **负面**: 违反边界规则需要额外的治理检查
