# ADR-002: 拒绝单体技能架构

- **状态**: ✅ 活跃
- **日期**: 2025-11-22
- **影响范围**: skills/

## 背景

初始方案采用单个大型技能文件承载所有功能，导致单次会话上下文消耗过大（> 50KB token），加载缓慢，且修改任意部分都需要重新验证整个技能文件。

## 决策

拒绝单体技能架构，改为**模块化技能架构**：

- 技能按领域独立组织为单独文件
- 每个技能文件聚焦单一职责
- 技能间通过明确接口通信
- 按需加载，不一次性全量注入

## 后果

- **正面**: 上下文消耗显著降低（单模块 < 10KB）
- **正面**: 技能可独立开发、测试和迭代
- **正面**: 修改局部不影响全局
- **负面**: 需要额外的技能路由和调度机制
- **负面**: 文件数量增加，管理复杂度上升
