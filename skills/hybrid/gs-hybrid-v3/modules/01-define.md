# 01 — DEFINE: 复杂度评估 + 需求澄清 + 确认

> 加载时机: DEFINE 态入口。结束后 user 确认需求方能进 PLAN。

## 复杂度分级判定

| 维度 | L1 简单 | L2 中等 | L3 复杂 |
|------|---------|---------|---------|
| 变更文件数 | < 3 | 3-8 | > 8 |
| 新增代码行 | < 100 | 100-500 | > 500 |
| 接口变更 | 无 | 新增 | 修改/删除 |
| 架构影响 | 无 | 局部 | 全局 |
| 风险等级 | 低 | 中 | 高 |

**L0 判定**（额外）: 1 文件、< 10 行、纯文本/配置修改。

### 决策树

```
架构重构? → 是 → L3
安全/性能关键路径? → 是 → L3
文件 > 8? → 是 → L3
代码 > 500? → 是 → L3
文件 ≥ 3? → 是 → 新增接口/模块? → L2
否则 → L1 (L0 检查 1 文件 < 10 行)
```

## 各级流程路径

| 级别 | 路径 |
|------|------|
| L0 | DEFINE(仅评估) → IMPLEMENT → SHIP |
| L1 | DEFINE → PLAN(轻量) → IMPLEMENT → SHIP |
| L2 | DEFINE → PLAN → IMPLEMENT → VALIDATE → SHIP |
| L3 | DEFINE → PLAN → IMPLEMENT → VALIDATE(多轮) → SHIP |

## 需求确认

DEFINE→PLAN 跃迁要求:

1. 与用户澄清需求范围、边界条件
2. 产出 spec 文件（格式自定，至少含需求清单）
3. **用户明确确认**（对话确认 + spec ## Approval 章节标记）
4. L0 豁免确认，直接进入 IMPLEMENT

### 评估输出模板

```
## 复杂度评估报告
- 新增/修改/删除文件: X / X / X
- 预估行数: XXX
- 影响分析: [API/DB/配置/部署]
- 评估结论: **L1/L2/L3**
```
