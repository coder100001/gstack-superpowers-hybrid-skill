# 04b — Execution Layer: SELF_REVIEW → QA

> **Context Load**: 加载 `execution-layer/review.md`, `execution-layer/validation.md`（SELF_REVIEW 阶段）。

## SELF_REVIEW 状态

**触发条件**: L3 任务必须；L1/L2 可选，但必须执行最小自审

### 最小自审要求（所有级别）

即使是 L1 任务，也必须完成以下最小自审检查，不可跳过：

- [ ] **契约对照**: 实现是否与 Context Layer 注水的约束一致？
- [ ] **冻结项检查**: 是否触碰了决策冻结项（架构/需求/API/领域边界）？
- [ ] **测试通过**: 所有测试是否通过？

> L1/L2 可跳过完整的测试策略自审和安全扫描，但以上 3 项不可省略。

### 目标

在 Execution Layer 内进行自审，确保代码质量、测试策略完善、边界条件覆盖充分，并符合 Governance 层的安全规则。

### 代码规则审查

代码规则审查委托给 [execution-layer/review.md](../../../../execution-layer/review.md)，按规则驱动审查流程执行：
1. 加载编码标准（coding-standards/index.md）
2. 按严重级别扫描 changed files（error → 必须修复 / warning → 建议修复 / info → 记录）
3. AI 行为红线检查（AI-R001 ~ AI-R008）
4. 语言特定规则检查（TS-* / GO-*）
5. 通用规则检查（SEC-* / DOC-* / ORG-*）
6. 生成规则检查摘要 → 如果有 error 违规则审查不通过

**此处不再重复编码规则清单，以 review.md 为准。**

### 2. 安全规则检查（委托 gstack:cso）

**规则**: SELF_REVIEW 阶段的安全检查不再依赖 AI 自审清单，而是委托给 `gstack:cso` 技能。

#### 触发条件

| 条件 | 动作 |
|------|------|
| 代码涉及用户输入处理 | 调用 `gstack:cso` 进行输入验证扫描 |
| 代码涉及认证/授权逻辑 | 调用 `gstack:cso` 进行身份权限扫描 |
| 代码涉及敏感数据（密钥、Token、密码） | 调用 `gstack:cso` 进行敏感信息扫描 |
| 代码涉及网络通信 | 调用 `gstack:cso` 进行通信安全扫描 |
| L3 任务（无条件） | 调用 `gstack:cso` 进行完整安全扫描 |

#### AI 自审保留项（最小化）

仅保留 AI 可可靠自检的项目：

- [ ] **密钥硬编码检查** — 搜索代码中的明文密钥/密码
- [ ] **日志脱敏检查** — 确认日志输出不包含敏感字段
- [ ] **错误信息泄露检查** — 确认错误返回不包含内部细节

#### 安全扫描工具调用

```bash
# Go 项目
gosec ./...

# Python 项目
bandit -r src/

# Node.js 项目
npm audit
```

**扫描结果必须记录到自审报告。**

## 安全异常处理

### 发现安全问题的处理流程

```
发现问题 → 评估风险 → 紧急修复 → 重新自审 → QA 验证
```

### 风险分级

| 级别 | 定义 | 响应时间 | 处理方式 |
|------|------|---------|---------|
| **Critical** | 可导致系统被完全攻破 | 立即 | 停止所有工作，立即修复 |
| **High** | 可导致严重数据泄露 | 24小时 | 优先修复 |
| **Medium** | 可导致有限影响 | 1周内 | 计划修复 |
| **Low** | 影响较小 | 下次迭代 | 记录跟踪 |

### 修复验证

修复后必须：
1. 重新运行安全扫描
2. 验证修复有效性
3. 确认无回归问题
4. 更新自审报告
