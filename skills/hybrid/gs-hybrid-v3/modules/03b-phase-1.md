# 03b - Phase 1: 逻辑规划

**触发条件**: 所有级别任务 (L1/L2/L3)

**调用 Skill**: `writing-plans`

## 目标

基于确认的方案，生成详细的实施计划 (PLAN.md)，包含：
- 具体的文件变更清单
- 边界条件识别
- 风险评估
- 验收标准

---

## 规划流程

```
方案理解 → 任务分解 → 依赖分析 → 风险评估 → 计划编写
```

---

## 步骤详解

### 1. 方案理解

**必须回顾**:
- Phase 0.6 确认的方案
- Design Doc 中的设计决策
- 相关的技术约束

### 2. 任务分解

**分解原则**:
- 每个任务对应一个文件或一个逻辑单元
- 任务粒度：可在 30 分钟内完成
- 任务之间有明确的依赖关系

**任务清单模板**:

```markdown
## 任务清单

### 任务 1: [任务名称]
- **目标**: ...
- **文件**: `path/to/file.go`
- **依赖**: 任务 X
- **验收标准**: ...
- **预估时间**: 30min

### 任务 2: ...
```

### 3. 依赖分析

**识别依赖**:
- 文件之间的依赖
- 模块之间的依赖
- 外部服务的依赖
- 数据迁移的依赖

**依赖图**:
```
任务 A → 任务 B → 任务 C
   ↓
任务 D
```

### 4. 风险评估

**评估维度**:
- 技术风险
- 时间风险
- 依赖风险
- 回滚风险

**风险登记册**:
| 风险 | 概率 | 影响 | 缓解措施 | 负责人 |
|------|------|------|---------|--------|
| ... | 高/中/低 | 高/中/低 | ... | ... |

## Phase 1.5: Plan验证确认 (IMPROVED!)

**触发条件**: 所有级别任务 (L1/L2/L3)

<HARD-GATE>
**这是强制阻断点！** 用户必须明确确认 PLAN，AI 才能开始编码。
</HARD-GATE>

### 验证清单

#### 范围验证
- [ ] 任务清单是否完整？
- [ ] 是否有遗漏的边界条件？
- [ ] 验收标准是否清晰可测？

#### 风险验证
- [ ] 识别的风险是否全面？
- [ ] 缓解措施是否可行？
- [ ] 是否有未考虑到的风险？

#### 验收标准验证
- [ ] 验收标准是否可测试？
- [ ] 是否有明确的通过/失败标准？
- [ ] 非功能需求是否被覆盖？

### 确认对话模板

```
AI: PLAN.md 已生成，请审查以下内容：

【范围摘要】
- 任务数: X 个
- 预估时间: X 小时
- 涉及文件: X 个

【风险摘要】
- 高风险: X 个
- 中风险: X 个
- 低风险: X 个

【验证清单】
1. 任务范围是否完整？
2. 边界条件是否充分？
3. 验收标准是否清晰？
4. 风险评估是否准确？

请确认：
✅ 确认 PLAN，开始执行
📝 需要修改 PLAN
❌ 放弃此方案

[等待用户明确回复]
```

### 阻断规则

- ❌ 用户未回复 → 等待
- ❌ 用户要求修改 → 修改后重新验证
- ❌ 用户放弃 → 回到 Phase 0.6
- ✅ 用户确认 → 继续 Phase 2

### 输出要求

必须记录：
- 用户确认时间
- 确认时的 PLAN 版本
- 任何修改意见
- 风险接受声明
