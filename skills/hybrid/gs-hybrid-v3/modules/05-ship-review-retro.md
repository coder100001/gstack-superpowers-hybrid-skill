## SHIP_REVIEW 阶段

**触发条件**: QA 验证通过后

### 目标

最终交付审查，确认可交付状态。

### 最终检查

#### 交付前检查
- [ ] 所有测试通过
- [ ] 代码审查通过
- [ ] 文档已更新
- [ ] Changelog 已生成
- [ ] 部署文档已准备

#### 用户确认

```
AI: 所有开发和验证已完成，请确认以下内容：

【交付摘要】
- 实现功能: X 个
- 修改文件: X 个
- 测试覆盖: XX%
- 代码质量: ✅

【交付物】
- 代码: [分支/提交]
- 测试报告: [链接]
- Changelog: [链接]
- 部署文档: [链接]

【验证结果】
- 功能验证: ✅ 通过
- 质量验证: ✅ 通过
- 安全验证: ✅ 通过

请确认：
✅ 确认交付
📝 需要修改
❌ 放弃交付

[等待用户确认]
```

### 输出要求

生成《验证交付报告》：

```markdown
# 验证交付报告

## 功能验证

- [ ] 需求覆盖
- [ ] 场景测试
- [ ] 边界条件

## 质量验证

- [ ] 代码质量
- [ ] 测试质量
- [ ] 性能质量

## 安全验证

- [ ] 安全扫描
- [ ] 敏感信息

## 交付物

- [ ] 代码
- [ ] 测试报告
- [ ] Changelog
- [ ] 部署文档

## 交付结论

**状态**: ✅ 可交付 / ⚠️ 有条件交付 / ❌ 不可交付

**备注**: ...
```

## RETRO 复盘阶段

**触发条件**: SHIP_REVIEW 完成后

**调用 Skill**: `gstack:retro`（L3 任务）

### 目标

记录本次任务的经验教训，持续改进。

### 复盘内容

#### 成功经验

- [ ] 本次任务做得好的地方
- [ ] 有效的工作方法
- [ ] 值得复用的技术方案

#### 问题与改进

- [ ] 遇到的问题
- [ ] 问题原因分析
- [ ] 改进措施

#### 技术收获

- [ ] 学习到的新技术
- [ ] 踩过的坑
- [ ] 最佳实践

#### 流程优化建议

- [ ] 流程中可以改进的地方
- [ ] 工具使用建议
- [ ] 协作方式优化

### 复盘报告模板

```markdown
# 复盘报告

## 项目信息
- 任务名称: [项目名称]
- 时间: [YYYY-MM-DD]
- 参与人: [名单]

## 成功经验
1. ...
2. ...

## 问题回顾
| 问题 | 原因 | 影响 | 解决方案 |
|------|------|------|----------|
| ...  | ...  | ...  | ...      |

## 改进计划
- [ ] 改进项 1: 责任人 + 截止时间
- [ ] 改进项 2: 责任人 + 截止时间

## 技术收获
- ...
- ...

## 下次注意
- ...
- ...
```
