# 03a - Step 0 + Phase 0.5 + Phase 0.6

## Step 0: 复杂度评估

**触发条件**: 任何任务开始前

### 评估步骤

1. **统计变更范围**
   - 列出所有需要新增、修改、删除的文件
   - 预估每处变更的代码行数
   - 识别哪些文件属于核心业务逻辑

2. **识别架构影响**
   - 是否修改接口定义？
   - 是否影响数据流？
   - 是否涉及配置变更？
   - 是否需要更新文档？

3. **评估风险等级**
   - 是否涉及数据迁移？
   - 是否影响现有用户？
   - 是否可回滚？
   - 是否有外部依赖？

4. **确定复杂度级别**
   - 根据判定标准确定 L1/L2/L3
   - 记录评估理由
   - 告知用户评估结果

### 输出要求

必须输出《复杂度评估报告》，包含：
- 变更文件清单
- 预估代码行数
- 影响分析
- 复杂度级别判定
- 建议的流程路径

## Phase 0.5: Design Doc (研究 & 设计)

**触发条件**: L2+ 任务 (L1 可选)

### 目标

产出编号设计文档，记录重大功能/改动的调研、设计决策和演进理由。

### 设计文档流程

```
需求澄清 → 方案调研 → 方案对比 → 设计决策 → 文档编写
```

### 步骤详解

#### 1. 需求澄清 (使用 brainstorming skill)

**必须提问的问题**:
- 这个功能要解决什么问题？
- 目标用户是谁？
- 有哪些约束条件？
- 成功的标准是什么？
- 有哪些已知的风险？

**禁止行为**:
- ❌ 不要假设需求
- ❌ 不要跳过提问直接设计
- ❌ 不要只提出一个方案

#### 2. 方案调研

**调研维度**:
- 业界最佳实践
- 类似项目的实现方式
- 技术选型的优缺点
- 潜在的坑和解决方案

#### 3. 方案对比

**必须对比至少 2-3 个方案**:

| 方案 | 优点 | 缺点 | 适用场景 | 复杂度 |
|------|------|------|---------|--------|
| A | ... | ... | ... | L? |
| B | ... | ... | ... | L? |
| C | ... | ... | ... | L? |

#### 4. 设计决策

**决策依据**:
- 为什么选这个方案？
- 放弃了什么？为什么？
- 未来的扩展性如何？
- 维护成本如何？

### 设计文档模板

```markdown
# Design Doc: [功能名称]

## 编号
`specs/design-docs/001-feature-name.md`

## 背景与问题
[描述要解决什么问题]

## 目标
- [ ] 目标1
- [ ] 目标2

## 方案对比

### 方案 A: [名称]
**优点**:
- ...

**缺点**:
- ...

### 方案 B: [名称]
...

## 决策
选择 **方案 X**，理由：
1. ...
2. ...

## 详细设计
[架构图、数据流、接口定义等]

## 风险评估
| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| ... | 高/中/低 | 高/中/低 | ... |

## 验收标准
- [ ] 标准1
- [ ] 标准2

## 相关文档
- [链接1]
- [链接2]
```

## Phase 0.6: 方案审核确认 (NEW!)

**触发条件**: 所有级别任务 (L1/L2/L3)

<HARD-GATE>
**这是强制阻断点！** 用户必须明确确认方案选择，AI 才能继续。
</HARD-GATE>

### 目标

在 Design Doc 完成后、Plan 创建前，确保用户对方案有充分理解并明确选择。

### 必须展示的内容

1. **方案对比表格**
   - 至少 2-3 个可选方案
   - 清晰的优缺点对比
   - 复杂度评估

2. **AI 推荐方案**
   - 明确推荐哪个方案
   - 详细的推荐理由
   - 风险提示

3. **用户确认**
   - 等待用户明确回复
   - 不能默认选择
   - 不能跳过

### 确认对话模板

```
AI: 基于需求分析，我提出了以下方案：

【方案对比表】

我推荐采用【方案 X】，理由：
1. ...
2. ...

⚠️ 风险提示：...

请确认：
1. 您是否同意选择【方案 X】？
2. 或者您倾向于其他方案？
3. 是否有其他考虑因素？

[等待用户明确回复]
```

### 阻断规则

- ❌ 用户未回复 → 等待
- ❌ 用户回复模糊 → 追问澄清
- ❌ 用户选择不同方案 → 重新评估影响
- ✅ 用户明确确认 → 继续 Phase 1

### 输出要求

必须记录：
- 用户选择的方案
- 选择理由
- 确认时间
- 相关风险接受声明
