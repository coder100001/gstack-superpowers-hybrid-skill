# Superpowers + GStack 混合流程 v4.0 (模块化)

> 结合 Superpowers 方法论和 GStack 工程标准的混合流程
> **v4.0 更新**: 模块化按需加载设计，优化上下文使用效率

---

## 快速开始

### 启动指令

| 指令 | 功能 | 说明 |
|------|------|------|
| `/plan` | 规划流程 | 新功能开发前的完整规划 |
| `/review` | 代码审查 | 代码完成后的质量审查 |
| `/test` | 测试驱动 | TDD 开发流程 |
| `/ship` | 发布准备 | 提交前的最终检查 |
| `/qa` | 质量保证 | 功能完成后的验证 |
| `/debug` | 调试助手 | 问题诊断与修复 |

### 标准工作流

```
用户: "hybrid 帮我开发新功能"

AI: 收到。我将按照 Superpowers + GStack Hybrid 流程执行：

Step 0:     评估任务复杂度 (L1/L2/L3)
Phase 0.5:  L2+ 创建 Design Doc
Phase 0.6:  方案审核确认 (用户必须确认)
Phase 1:    生成详细 PLAN.md
Phase 1.5:  Plan验证确认 (用户必须确认)
Phase 2-3:  工程规范 + 架构评审 (L2+)
Phase 4-5:  QA + 安全评审 (L3)
Phase 6:    TDD 编码实现
Phase 7:    验证交付
```

## 模块化设计

本 Skill 采用**按需加载**设计，将完整流程拆分为多个模块，根据当前阶段动态加载，避免一次性加载所有内容消耗上下文。

### 模块索引

| 模块 | 内容 | 加载时机 |
|------|------|---------|
| [01-intro](./modules/01-intro.md) | 快速开始、项目配置、核心概念 | 初始加载 |
| [02-complexity](./modules/02-complexity.md) | 复杂度分级、适用矩阵 | Step 0 |
| [03a-phase-0-06](./modules/03a-phase-0-06.md) | Step 0 + Phase 0.5 + 0.6 | Step 0-0.6 |
| [03b-phase-1](./modules/03b-phase-1.md) | Phase 1 逻辑规划 | Phase 1 |
| [04a-phase-2-3](./modules/04a-phase-2-3.md) | Phase 2-3 工程规范与架构评审 | Phase 2-3 |
| [04b-phase-4-5](./modules/04b-phase-4-5.md) | Phase 4-5 QA/安全评审 | Phase 4-5 |
| [05-phase-6-7](./modules/05-phase-6-7.md) | Phase 6-7 编码与验证 | Phase 6-7 |
| [06-workflows](./modules/06-workflows.md) | 专用流程指令 | 指令触发 |
| [07-handling](./modules/07-handling.md) | 异常处理机制 | 异常发生时 |
