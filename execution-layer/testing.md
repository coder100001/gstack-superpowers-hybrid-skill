# Testing Rules

> **层**: Execution Layer · **职责**: 验证实现质量
> **前置条件**: 代码实现已完成（见 implementation.md）
> **禁止**: 跳过测试、伪造测试覆盖、测试与实现分离

---

## 1. 测试分层

### 1.1 单元测试
- **范围**: 单个函数、类、模块
- **目标**: 验证内部逻辑正确性
- **覆盖率**: 公开 API 100%，核心逻辑 90%+
- **执行速度**: < 10ms/测试
- **隔离性**: 完全独立，无外部依赖

### 1.2 集成测试
- **范围**: 模块间交互、API 契约
- **目标**: 验证组件协作
- **覆盖率**: 关键集成路径 100%
- **执行速度**: < 100ms/测试
- **隔离性**: 最小化外部依赖（使用 mock/stub）

### 1.3 E2E 测试
- **范围**: 完整用户流程
- **目标**: 验证端到端功能
- **覆盖率**: 核心用户路径 100%
- **执行速度**: 按需运行
- **隔离性**: 使用测试环境

---

## 2. 覆盖率要求

| 层级 | 行覆盖 | 分支覆盖 | 函数覆盖 |
|:-----|:-------|:---------|:---------|
| 单元测试 | ≥ 80% | ≥ 70% | ≥ 90% |
| 集成测试 | ≥ 60% | ≥ 50% | ≥ 70% |
| E2E 测试 | - | - | ≥ 80%（核心路径） |

**红线**: 未达标的代码不得合并。

---

## 3. 测试策略

### 3.1 TDD 流程
```
Red → Green → Refactor
  ↓        ↓         ↓
失败测试  最简实现  契约内优化
```

### 3.2 测试文件结构
```
src/
  ├── module.ts
  └── module.test.ts
tests/
  ├── integration/
  └── e2e/
```

### 3.3 测试命名规范
- `should{行为}When{条件}`
- 示例: `shouldReturnUserWhenValidId`

---

## 4. 禁用测试反模式

### 4.1 绝对禁止
- ❌ 测试与实现耦合过紧
- ❌ 忽略边缘情况
- ❌ 测试依赖执行顺序
- ❌ 硬编码测试数据
- ❌ 伪造测试覆盖

### 4.2 不推荐
- ⚠️ 过度使用 mock
- ⚠️ 测试重复代码
- ⚠️ 慢测试（> 1s）
- ⚠️ 无断言的测试

---

## 5. 测试执行

### 5.1 本地执行
```bash
# 单元测试
npm test -- --watch

# 集成测试
npm run test:integration

# 全量测试
npm run test:all
```

### 5.2 CI/CD 执行
- 每次提交: 单元测试 + 覆盖率检查
- PR 时: 全量测试
- 发布前: E2E 测试
