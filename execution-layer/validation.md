# Validation Rules

> **层**: Execution Layer · **职责**: 交付验收
> **前置条件**: 代码审查通过（见 review.md）
> **禁止**: 跳过验收、降低标准、带病上线
> **阻断规则**: 任何 P0 项不通过 = 禁止进入 SHIP_REVIEW

---

## 1. 用户验收标准（UAT）

### 1.1 功能验收（P0 — 阻断）

| 验收项 | 判定标准 | 阻断级别 |
|:-------|:---------|:---------|
| 需求功能完整性 | 所有 REQUIREMENT_LOCK 中列出的功能 100% 实现 | P0 阻断 |
| 用户流程可用性 | 所有核心用户路径端到端通过 | P0 阻断 |
| 边界情况处理 | 空值/越界/并发等边界输入不崩溃，返回定义的错误码 | P0 阻断 |
| 错误提示清晰度 | 错误消息包含可操作的修复建议（非仅 "Error"） | P1 建议 |
| 用户体验符合度 | UI/UX 符合设计稿（如有），偏差 ≤ 5% | P2 优化 |

### 1.2 验收流程

```
准备阶段 → 执行阶段 → 签字确认
   ↓           ↓           ↓
环境准备    用例执行    验收报告
数据准备    问题记录    交付确认
```

## 2. 质量验证

### 2.1 质量指标（P0 — 阻断）

| 指标 | 阈值 | 测量方法 | 阻断级别 |
|:-----|:-----|:---------|:---------|
| 文档引用完整性 | 100%（0 个断裂引用） | `validate-project.sh` | P0 阻断 |
| 规范符合度 | 0 个 error 级别违规 | coding-standards 规则检查 | P0 阻断 |
| 测试覆盖率 | ≥ test-spec.md 定义的最低阈值 | 覆盖率工具（见 test-spec §2） | P0 阻断 |
| AI 行为红线 | AI-R001~R008 全部通过 | SELF_REVIEW 输出 | P0 阻断 |
| 技能触发精准度 | 无误触发 | 测试验证 | P1 建议 |
| 文件完整性 | 无缺失引用 | 引用检查 | P1 建议 |

### 2.2 质量验证检查

- 文档验证：`validate-project.sh` 通过 = 引用完整性达标
- 技能验证：模块可加载 + 路由正确
- 规范验证：coding-standards 规则检查 0 error
- 完整性验证：`validate-skills.sh` 通过

## 3. 安全验证

### 3.1 安全检查（按触发条件分级）

| 检查项 | 判定标准 | 触发条件 | 阻断级别 |
|:-------|:---------|:---------|:---------|
| 输入验证完整 | 所有外部入口有验证逻辑 | 所有变更 | P0 阻断 |
| 认证授权正确 | 写操作必须认证，权限检查无绕过 | 涉及认证/授权代码 | P0 阻断 |
| 敏感数据加密 | 密钥/令牌/PII 不出现在日志和响应中 | 涉及敏感数据 | P0 阻断 |
| 无注入漏洞 | SQL/命令/路径注入扫描 0 Critical | 涉及数据库/命令执行 | P0 阻断 |
| 无 XSS/CSRF | 前端输入输出编码正确 | 涉及前端渲染 | P1 建议 |
| 依赖无已知漏洞 | `npm audit` / `go vuln` 0 Critical/High | 所有变更 | P0 阻断 |
| 错误信息不泄露 | 错误响应不含堆栈/SQL/文件路径 | 所有变更 | P1 建议 |

### 3.2 安全测试触发矩阵

| 变更类型 | SAST | 依赖扫描 | DAST | 渗透测试 |
|:---------|:----:|:--------:|:----:|:--------:|
| L1 通用变更 | 可选 | 必须 | 不要求 | 不要求 |
| L2 涉及认证/授权 | 必须 | 必须 | 可选 | 不要求 |
| L2 涉及数据存储 | 必须 | 必须 | 可选 | 不要求 |
| L3 安全敏感系统 | 必须 | 必须 | 必须 | 必须 |

## 4. 部署验证

### 4.1 部署前检查（P0 — 阻断）

| 检查项 | 判定标准 | 阻断级别 |
|:-------|:---------|:---------|
| 所有测试通过 | CI 全量测试 0 失败 | P0 阻断 |
| 代码审查完成 | SELF_REVIEW 输出 0 error | P0 阻断 |
| 发布文档齐全 | CHANGELOG + 迁移指南（如有破坏性变更） | P0 阻断 |
| 回滚方案准备 | 回滚步骤文档化且可执行 | P1 建议 |
| 监控告警配置 | 关键指标有告警规则 | P1 建议 |

### 4.2 部署流程

```
1. 预发布环境验证
   ├─ 功能回归测试：核心路径 100% 通过
   ├─ 性能验证：响应时间 ≤ 基线 120%
   └─ 安全扫描：0 Critical/High 漏洞

2. 灰度发布
   ├─ 10% 流量，持续 ≥ 15 分钟
   ├─ 监控关键指标：错误率 < 1%，延迟 P99 < 基线 150%
   └─ 逐步扩大：10% → 50% → 100%

3. 全量发布
   ├─ 持续监控 ≥ 30 分钟
   ├─ 日志跟踪：无 ERROR 级别异常增长
   └─ 异常告警：自动触发回滚条件
```

### 4.3 部署后验证（P0 — 阻断）

| 验证项 | 判定标准 | 阻断级别 |
|:-------|:---------|:---------|
| 系统正常启动 | 健康检查端点返回 200 | P0 阻断 |
| 关键功能正常 | 核心用户路径冒烟测试通过 | P0 阻断 |
| 性能指标正常 | 响应时间 ≤ 基线 120% | P1 建议 |
| 无错误日志 | ERROR 级别日志无异常增长 | P1 建议 |
| 监控数据正常 | 关键指标在正常范围内 | P1 建议 |

## 5. 验收交付

### 5.1 交付标准

| 标准 | 判定方式 |
|:-----|:---------|
| P0 项全部通过 | 量化条件全部满足 |
| P1 项 ≥ 80% 通过 | 允许 20% 的 P1 项有已知限制，但必须记录 |
| P2 项按需 | 不阻断交付 |

### 5.2 交付物

| 交付物 | 格式 | 必须 |
|:-------|:-----|:-----|
| 验收测试报告 | Markdown，含通过/失败明细 | 必须 |
| 覆盖率报告 | 覆盖率工具输出 | 必须 |
| 安全扫描报告 | SAST/依赖扫描输出 | L2+ 必须 |
| 部署操作手册 | Markdown，含回滚步骤 | L2+ 必须 |
| 性能测试报告 | 基准对比数据 | L3 必须 |

## 6. 异常处理

### 6.1 问题分级

| 级别 | 定义 | 响应时间 | 阻断级别 |
|:-----|:-----|:---------|:---------|
| P0 | 系统不可用 / 数据丢失 / 安全漏洞 | 立即处理 | 阻断交付 |
| P1 | 核心功能异常 / 性能严重下降 | 1h 内 | 阻断交付 |
| P2 | 功能受损但可规避 | 4h 内 | 不阻断，记录 |
| P3 | 体验问题 / 优化建议 | 24h 内 | 不阻断，记录 |

### 6.2 回滚触发条件

| 触发条件 | 判定标准 | 操作 |
|:---------|:---------|:-----|
| P0/P1 问题 | 无法在 30 分钟内修复 | 立即回滚 |
| 性能严重下降 | 响应时间 > 基线 200% | 立即回滚 |
| 安全问题暴露 | Critical 漏洞被利用 | 立即回滚 |
| 数据异常 | 数据不一致或丢失 | 立即回滚 |
